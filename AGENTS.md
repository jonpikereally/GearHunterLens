# Brief for anyone (human or AI) working on Gear Hunter Lens

Gear Hunter Lens is a Manifest V3 extension (Brave/Chrome/Edge). Plain JS, no build step, no dependencies. It's a port of Marketplace Lens (jonpikereally/MarketplaceLens) to Long & McQuade's GearHunter, with the same release and error-code conventions (sibling of FakeSale too).

- **Card detection** (`src/content.js`): item cards are `a[href*="/GearHunter/"]` whose path matches `/GearHunter/<number>/` (`ITEM_ID`); department links have no number and are skipped. Each link wraps the whole card: name in its `title`, then "Sale Price: $X", "or from: $Y/mo" (financing, ignored), "Regular Price: $Z", and the store ("City," / "Province" / phone). The grid cell (`div.m-item`, found via `cellOf`) is what "Remove" collapses. The card box inside the link (`.products-item`, class `mlens-host`) carries the blur/cover and tags, so they don't spill into the grid gutters.
- **Seen** = the whole cell is ≥98% inside the viewport for `settings.seenMs` (GearHunter has no pinned header). Item pages (`.gear-hunter-sale-price`, `.gear-hunter-regular-price`, `h2.text-capitalize`; the h1 just says "Gear Hunter") count as seen after 1.5 s.
- **Hiding** happens for items seen *before this tab loaded* (`seenThisTab`), unless `hideRightAway` is on. Price-changed cards are never hidden that visit, and keep their tag (`changedThisTab`). Clicking a cover adds the id to `revealedThisTab`; clicks are swallowed in the window's capture phase so the item link doesn't open. Covered cards never count as seen.
- **Hide styles** (`settings.hideStyle`): `blur` (default; strength `settings.blurPx` via the `--mlens-blur` CSS variable), `cover` (solid panel), `collapse` (`html.mlens-collapse`, `display:none` on the cell).
- **Manual rejection:** the record gets `x` (rejected-at time), `xp`/`xv` (price text and value when rejected). `render()` checks `rec.x` before anything else, so a rejected item is covered (`.mlens-cover.rejected`, always opaque, even in blur mode or peek; removed in "collapse" mode) on every visit, never expires and ignores price changes, except for the note on its panel. The ✕ hover button is `.mlens-reject` (`data-act="reject"`/`"unreject"`); covers carry `data-act` links too. All are handled by `setRejected()` from the window capture-phase click handler, and other tabs follow through `storage.onChanged`.
- **DOM writes must be idempotent.** The MutationObserver rescans on page changes, so `render()`/`tag()`/`cover()` only touch the DOM when something differs, and the observer ignores our own `.mlens-tag` / `.mlens-cover` / `.mlens-reject` elements. Otherwise the page re-scans forever.
- **Storage:** `chrome.storage.local`, one `l:<item number>` key per item: `{ f firstSeen, s lastSeen, t name, i image, u url, l store, r regular price, price, value, h: [{t,p,v}] (last 20 prices), c lastPriceChange }`, plus `settings`, `errors` and `update`. Never rename keys without a migration.
- **Errors:** every user-facing error has a `GH-###` code in `src/shared/errors.js`, documented in `ERRORS.md`; `scripts/check-errors.sh` enforces this.
- **Testing:** `node tests/content.test.mjs`, plus the two pages in `tests/`. In an embedded or background browser that isn't painting frames, IntersectionObserver never fires, so take screenshots to drive rendering when automating.
- **Releases:** bump `manifest.json` version + `RELEASE_NOTES.txt`, push to `main`; the Action builds `updates/`.
